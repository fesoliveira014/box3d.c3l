# Binding conventions

Contributing › Binding conventions

How a box3d C symbol becomes C3 in this package. [style.md](style.md) is the baseline; this page
refines it for the binding and records where it deliberately departs. The `add-binding` skill in
`.claude/skills/` applies these rules step by step.

## Layout of `src/`

- One pair per area of the C API: `src/<area>.c3i` holds the types and raw `extern fn`
  declarations, `src/<area>.c3` the wrappers over them. A new area adds a pair. Read the set from
  the directory; do not list it in prose, because lists go stale.
- Three files are not a pair:
  - `src/check.c3`: the `faultdef`s, the per-type `.is_null()` and `.checked()` macros, and the
    shared private guards.
  - `src/layout.c3`: compile-time `$assert` layout pins, generated by `scripts/build-box3d.sh`.
    Never edit it by hand.
  - `src/base.c3i`/`src/base.c3`: library-level hooks (version, allocator, timer, length units).
- `manifest.json` names `"sources": [ "src/**" ]`. That key replaces the default scan of the
  package root, so a `.c3` file at the root is silently not compiled.
- Every file is `module b3;` except two optional subsystems: `src/draw.*` is `module b3::draw;`
  and `src/record.*` is `module b3::record;`. Both had a multi-word C prefix that the namespace now
  carries (`b3RecPlayer` is `record::Player`). Do not add a third submodule; the rest of the API is
  flat on purpose. Inside a submodule, a fault in a `@return?` is written `b3::NAME`.

## Names

- The `b3` prefix is the module name, never part of an identifier: `b3::create_world`, not
  `b3CreateWorld` or `b3::b3_create_world`. Functions `snake_case`, types `PascalCase`, constants
  and enum values `SCREAMING_SNAKE_CASE`. No `@builtin`; it defeats the namespace.
- An all-uppercase identifier parses as a constant, so acronyms fold: `b3AABB` is `Aabb`,
  `b3SATCache` is `SatCache`.
- Getters drop `get_`; setters keep `set_`. `b3World_GetGravity` is `world.gravity()`,
  `b3World_SetGravity` is `world.set_gravity(v)`.
- `@cname("...")` carries the real C symbol verbatim. `@extern` as a rename attribute was removed
  in 0.8.x.

## Method or free function

The C symbol decides, and nothing else does.

| C symbol | C3 | Kind |
|---|---|---|
| `b3Type_GetX` | `type.x()` | method |
| `b3Type_SetX` | `type.set_x(v)` | method |
| `b3Type_IsX`, `b3Type_AreX` | `type.is_x()` | method |
| `b3Type_EnableX(bool)` | `type.enable_x(v)` | method (a setter spelled with a verb) |
| contains `Compute` | `body.compute_aabb()` | method |
| anything else | `world_step(world, dt, sub)` | free function, receiver first |

A free function is named from the C symbol with `b3` stripped and nothing reordered:
`b3Body_ApplyForce` is `body_apply_force`, `b3RayCastSphere` is `ray_cast_sphere`,
`b3DestroyWorld` is `destroy_world`. The function keeps the C name's own type token
(`world_step`, not `world_id_step`).

When a wrapper takes the plain name, the extern it wraps takes a `_raw` suffix and `@private`:
`b3RayCastSphere` is `ray_cast_sphere_raw` (extern) and `ray_cast_sphere` (wrapper). The `_raw`
name follows the C order too; never `sphere_ray_cast_raw`.

Four kinds of helper this package invented, rather than bound, stay methods: `.is_null()` and
`.checked()`; `JointId.as_motor()` and its seven siblings; and the wrappers that turn a C
count-and-pointer pair into a slice (`world.contact_begin_touch_events()`, `body.shapes()`). They
read a value out of something rather than operating on it.

## Types and layout

- Never bind from memory. Read the declaration in `build/box3d-src/include/box3d/*.h`, the patched
  copy the build uses (`vendor/box3d/` lacks what a patch adds). A wrong
  parameter or return type is a silent cross-ABI memory bug.
- The IDs (`b3WorldId`, `b3BodyId`, `b3ShapeId`, `b3JointId`, `b3ContactId`, …) are value structs
  passed and returned by value. Declare their fields exactly as the header does. Never model an ID
  as `inline void*`; it corrupts the ABI silently. Use an opaque type only for something that is a
  pointer in C (`b3RecPlayer*`), after confirming it in the header.
- A struct C3 reads is declared in full, field for field, in header order.
- A C struct that embeds another as its first member binds as `inline`
  (`struct FilterJointDef { inline JointDef base; }`).
- A closed C set becomes an `enum`; a flag set becomes a `bitstruct X : uint`.
- A type that crosses the public API cannot be `@private`: consumers could not name it. A box3d
  object handed back by pointer has public fields or is an opaque `typedef X = void`.
- A method cannot share a name with a field of its struct. Where box3d's getter is a bare field
  read, drop it and let callers read the field (`tree.proxy_count`). Slice accessors over a field
  take a qualified name (`Manifold.contact_points()`).
- A slice over a struct's own inline array needs a `&self` receiver; a by-value receiver returns a
  slice into a dead copy.

### Layout pins

Pins are generated. Add the C type and its fields to `scripts/abi-types.txt`, then run
`./scripts/build-box3d.sh --update`. The script probes the real headers, rewrites
`scripts/abi-sizes.txt`, and regenerates `src/layout.c3`, converting C names to C3 spellings.

`abi-types.txt` syntax, one type per line:

| Form | Meaning |
|---|---|
| `b3WorldDef a,b,c` | pin size, alignment, and every listed field's offset and name; list every field, the pins are positional |
| `b3X=Y` | the C3 name is `Y` verbatim (the `b3Rec*` family, whose prefix `b3::record` carries) |
| `@name` field | pin the offset only; for the first arm of an anonymous union, which C3 reports unnamed |
| `-name` field | probe and record, pin nothing; for a C3 spelling with no positional members (`b3Matrix3` is `Matrix3f`) |

`--check` fails when the probe or `src/layout.c3` drifts. Never update the record to silence a
drift unless the binding changes to match in the same commit.

## Wrappers are where errors become faults

The `extern fn` layer stays faithful to C: raw return types, raw out-parameters, no
interpretation. The wrapper layer is what callers use.

- Fallible operations return optionals with named faults from `src/check.c3`. Never return
  null-as-error, a sentinel, or a raw C status code. Add a `faultdef` (one per line) only when no
  existing fault fits.
- An invalid or zero ID returned by C becomes a fault.
- Out-parameters become return values; count-and-pointer pairs become slices.
- `create_x`/`destroy_x` are free functions without exception; `defer catch` owns failure-only
  cleanup.
- Definitions passed to a constructor must come from the matching `default_*_def()`. box3d's
  cookie assertion is compiled out of the shipped Release build, so the wrapper compares the
  cookie and refuses with `INVALID_DEFINITION`.
- Per-call validity checking is opt-in through the `.checked()` macros, not on by default,
  because a step touches thousands of bodies. The `BOX3D_CHECKED` feature gates no wrapper; only
  `checked_access()` reads `$feat(BOX3D_CHECKED)`, for callers that branch on it.

### Pointer parameters

A caller-supplied pointer gets both `@param [&in]` and an explicit null guard:

```c3
if (def == null) return INVALID_DEFINITION~;
```

`[&in]` traps in a safe build, but a consumer's release build drops the check and the optimizer may
fold on the contract: a null read through and printed a value instead of crashing. The annotation
gives a safe build a precise message; the guard is what a release build has. If a future c3c
starts eliding the guard because of `[&in]`, drop the annotation, not the guard.

A null test cannot be a `.checked()` method: C3 traps a method call on a null receiver before the
body runs. Use a free macro taking the pointer (`checked_geometry`).

### Fault lists

Every fault a wrapper returns is declared with `@return?`, one directive per fault. The success
value keeps a plain `@return`.

```c3
<*
 @param [&in] def : `a definition obtained from default_world_def()`
 @return `the world`
 @return? INVALID_DEFINITION : `def is null, or did not come from default_world_def()`
 @return? WORLD_LIMIT_REACHED : `MAX_WORLDS worlds already exist`
*>
```

`@return? check_shape_proxy!` inherits a shared guard's faults instead of restating them.

What c3c 0.8.5_1 checks: a literal `return SOME_FAULT~;` in the body is checked against the list,
and an inherited name that does not resolve is a hard error. A fault arriving through
`callee(...)!`, `return callee(...)`, or a macro body is not checked, and neither is a declared
fault that is never returned. A clean build is not proof the list is complete.

## Deliberate departures from style.md

- §6 (`create_x`/`destroy_x` free functions) applies without exception.
- §3's file order (typedefs → aliases → constants → enums → structs → methods → functions) does
  not apply inside `src/<area>.c3i` or its wrapper. Declarations are grouped by area: a
  constructor sits next to the geometry it builds. Shared private guards (`check_shape_def`,
  `check_joint_def`, `check_joint_type`) go last in their file.
- §7's lean-docstring rule is relaxed to a hard cap; see [docstrings.md](docstrings.md).
- §5 (GPU, GLSL, compute) does not apply.
- §8's `c3c build`/`c3c test` describe a consuming project. This package's checks are in
  [testing.md](testing.md).

## C3 0.8.5_1 spellings

All confirmed against the compiler at `/home/fesol/opt/c3/c3c` (the `c3-linux-static` build; the
host glibc is too old for the stock release).

| Write | Not |
|---|---|
| `T::size`, `T::alignment` | `T::align`, `.sizeof` |
| `return SOME_FAULT~;` | `return SOME_FAULT?;` |
| `$feat(NAME)` | `$feature(NAME)` (deprecated, warns) |
| `ulong::max` | `~0u64`, `ulong.max` |
| `Aabb` | `AABB` (parses as a constant) |

- `@private` on a method is ignored with a warning. Only a free function is private, which is why
  shared guards and `_raw` externs that would be methods are free functions.
- Consecutive `case` labels with an empty body are one fall-through group. Use an `if` when a case
  does nothing.
- An optional cannot be a function parameter, and a plain macro parameter auto-propagates one. A
  helper that inspects an optional is an `@`-macro taking `#expr`.
- A bare decimal literal is a `double`. Compare a `float` against `(float)0.6` or a tolerance.
- Do not run `c3fmt`. It breaks the named-argument format and one-fault-per-line `faultdef`s.
